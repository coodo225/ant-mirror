# 🐜 개미들을 위한 투자정보

> 개미는 정말 늘 반대로 가는가. 그래서 틀렸는가.

한국 증시를 **수급**으로 읽는 대시보드. 개인·외국인·기관 세 주체의 돈이 어디로 흐르는지를
중심에 놓고, 지수·종목·업종과 미국장·환율·금리·FOMC 같은 바깥 맥락을 한 화면에 붙였습니다.

서버가 필요 없습니다. 데이터 수집은 GitHub Actions 가 대신 돌고, 페이지는 정적 파일만 읽습니다.

---

## 이 페이지의 태도

"개미는 외국인·기관과 늘 반대로 간다"는 말은 사실입니다.
실제로 최근 3년(750거래일) 중 **78.9%** 의 날에 개인과 외국인은 정반대 방향이었고,
두 주체의 일별 순매수 **상관계수는 −0.83** 입니다.

그런데 이건 아이러니가 아니라 **산수**입니다.
순매수 총합은 언제나 0이라, 누군가 사면 누군가는 반드시 팔아야 합니다.
개미가 유별나서가 아니라 시장이 그렇게 생겼습니다.

그래서 이 페이지가 던지는 질문은 방향이 아니라 **타이밍**입니다.
각 주체가 크게 사들인 날로부터 20거래일 뒤, 지수가 실제로 어떻게 됐는지를 시장 평균과 비교해
**성적표**로 만듭니다. 계산은 `collector/collect.py` 의 `build_ant()` 에 전부 들어 있습니다.

풍자는 톤에만 있고 숫자에는 없습니다. 데이터가 개미 편을 들면 페이지도 개미 편을 듭니다.
실제로 표본을 1년에서 3년으로 늘리자 개미의 학점은 F에서 C로 올라갔고, 페이지는 그 연도별
내역(2023 D → 2024 C → 2025 C → 2026 F)을 표로 그대로 보여줍니다. "개미는 늘 틀린다"보다
정확한 문장은 "개미는 급락하는 해에 유독 크게 틀린다"입니다. 상관관계가 인과가 아니라는 것도
**"성적표를 믿기 전에 읽을 것"** 섹션에서 스스로 밝힙니다.

목적은 조롱이 아닙니다. 개미가 지는 이유가 멍청해서가 아니라 늘 마지막에 정보를 받기 때문이라면,
필요한 건 같은 숫자를 같은 시각에 보는 일입니다.

## 왜 이런 구조인가

브라우저에서 KRX·네이버·FRED·야후를 직접 `fetch` 하는 방법은 **작동하지 않습니다.**
확인해 보면 이렇습니다.

| 소스 | 응답 | `Access-Control-Allow-Origin` |
|---|---|---|
| KRX 정보데이터시스템 | 403 (로그인 필요) | 없음 |
| 네이버 금융 | 200 | **없음** |
| 한국은행 ECOS | 200 | **없음** |
| Yahoo Finance | 200 | **없음** |
| FRED | 200 | 없음 |

CORS 헤더를 주는 곳이 하나도 없어서, 브라우저는 응답이 도착해도 스크립트에 넘겨주지 않습니다.
그래서 수집은 서버 쪽(=GitHub Actions)에서 하고, 결과 JSON 을 페이지와 **같은 오리진**에 놓습니다.

```
GitHub Actions (cron)
  └─ collector/collect.py
       ├─ 네이버 금융        → 개인/외국인/기관 수급, 지수, 시총상위, 업종
       ├─ FinanceDataReader  → 코스피/코스닥 일봉
       ├─ yfinance           → 미국 지수·선물·금리·환율·원자재
       └─ federalreserve.gov → FOMC 일정
            └─ docs/data/*.json 커밋
                 └─ GitHub Pages 가 docs/ 를 서빙 → 페이지가 같은 오리진에서 읽음
```

또 하나 알아둘 것. **개인·외국인·기관 수급에는 진짜 실시간이 없습니다.**
장중에 나오는 값은 잠정치(추정)이고, 확정치는 장 마감 후 저녁에 갱신됩니다.
그래서 화면 상단에 장 상태 배지와 잠정치 안내를 띄우고, 마감 후 실행에서 확정치로 정정합니다.

## 빠른 시작

```bash
python -m venv .venv
```

```bash
.venv/Scripts/python -m pip install -r collector/requirements.txt
```

```bash
.venv/Scripts/python collector/collect.py
```

`docs/data/*.json` 이 생기면 정적 서버로 열어 봅니다. (`file://` 로 열면 fetch 가 막힙니다.)

```bash
.venv/Scripts/python -m http.server 8765 --directory docs
```

브라우저에서 `http://localhost:8765` 로 접속합니다.

> macOS / Linux 는 `.venv/Scripts/python` 대신 `.venv/bin/python` 을 씁니다.

## 배포 (GitHub Pages)

1. 이 폴더를 GitHub 저장소로 올립니다.
2. **Settings → Pages → Source** 를 `Deploy from a branch`, 브랜치는 `main`, 폴더는 `/docs` 로 지정합니다.
3. **Settings → Actions → General → Workflow permissions** 를 `Read and write permissions` 로 바꿉니다.
   (워크플로가 `docs/data` 를 커밋해야 합니다.)
4. **Actions** 탭에서 `시장 데이터 수집` 을 한 번 수동 실행(`Run workflow`)해 봅니다.

이후 평일 장중에는 10분마다, 마감 후와 다음 날 아침에 한 번씩 자동 갱신됩니다.

### 저장소는 public 을 권합니다

Actions 스케줄 실행은 **public 저장소에서 무료**입니다.
private 이면 장중 10분 주기(하루 약 42회)로 무료 사용량을 빠르게 소진합니다.
private 으로 쓰려면 `collect.yml` 의 첫 cron 을 `*/30` 정도로 늘리세요.

> 참고: GitHub 는 60일간 커밋이 없는 저장소의 예약 워크플로를 자동 비활성화합니다.

## 선택: FRED API 키

미국 CPI·고용·PCE **발표 일정**과 CPI·기준금리·실업률 **실측치**를 함께 보려면
[FRED 무료 API 키](https://fred.stlouisfed.org/docs/api/api_key.html)를 발급받아
저장소 **Settings → Secrets and variables → Actions** 에 `FRED_API_KEY` 로 등록하세요.

없어도 나머지는 전부 정상 동작합니다. (미 노동통계국 BLS 사이트는 봇을 403으로 차단하므로
CPI 일정은 FRED 를 통해서만 자동으로 가져올 수 있습니다.)

로컬에서 쓸 때:

```bash
FRED_API_KEY=your_key .venv/Scripts/python collector/collect.py
```

## 화면 구성

| 섹션 | 내용 |
|---|---|
| **거울 한 줄** | 오늘 개미의 매수 강도에 따라 바뀌는 헤드라인. 무작위 농담이 아니라 오늘 숫자에서 나온 문장 |
| **오늘의 수급 줄다리기** | 세 주체의 순매수/순매도를 좌우 발산 막대로. 위쪽 띠는 파는 진영과 사는 진영의 구성비 |
| **🐜 개미 온도계** | 오늘 개인 순매수가 3년 분포에서 몇 번째 백분위인지. 상·하위 20% 에 들면 과거 같은 국면의 20일 성적을 붙여줌 |
| **외국인의 본심 (선물)** | 코스피200 선물 외국인 순매수 20일. 현물과 방향이 갈리면 다이버전스 경고 |
| **빚투 체온계** | 신용융자 잔고(코스피/코스닥), 반대매매 금액·비율, 투자자예탁금, 미수금 — 금융투자협회 공개 통계 |
| **지금 벌어지는 일** | 연속 매매, 수급 구도, 환율·VIX·반도체 지수를 문장으로 정리 |
| **지수** | 코스피·코스닥 현재가와 60일 스파크라인 |
| **성적표** | 주체별 A~F 학점(3년 표본) + 연도별 분해 — 개미 학점이 장세 탓인지 검증 가능 |
| **반대로 가는 본능** | 개미↔외인·기관 상관계수와 정반대였던 날의 비율. 옆에는 왜 그게 당연한지 설명 |
| **개미가 크게 질렀던 날들** | 지난 1년 최대 순매수 5일과 그 20거래일 뒤 성적. 잘 맞은 날도 그대로 표시 |
| **성적표를 믿기 전에 읽을 것** | 표본·장세 편향·인과 한계에 대한 자기 고백 |
| **수급 흐름** | 40/120거래일 누적·일별 순매수 3개 선(또는 막대) + 지수 종가 오버레이 |
| **연속 매매 기록** | 주체별 연속 매매 일수와 최근 10일 매매 방향 점 |
| **기관은 누가 움직였나** | 금융투자·투신·연기금·보험·은행·기타금융 분해 |
| **시가총액 상위 종목** | 면적=시총, 색=등락률 트리맵. 누르면 5일치 종목 수급 |
| **업종** | 상승·하락 상위 8개 업종 |
| **바깥 지표** | 미국 지수·선물, 반도체(SOX), VIX, 10년물, 환율, 달러인덱스, 유가, 금 |
| **다가오는 이벤트** | FOMC(점도표 여부 포함) D-day. FRED 키가 있으면 CPI·고용·PCE 추가 |

색은 한국 관례를 따릅니다. **빨강 = 상승·순매수, 파랑 = 하락·순매도.**

```json
  ]

```

## 데이터에 대한 주의

- 네이버 금융은 공식 API 가 아닙니다. 응답 구조가 예고 없이 바뀌면 수집이 깨질 수 있고,
  대량 요청은 서비스 약관에 저촉될 수 있습니다. 개인용 갱신 주기를 지키세요.
  KRX 공식 데이터를 쓰려면 `data.krx.co.kr` 무료 계정을 만들어 로그인 세션으로 접근해야 합니다.
- 장중 수급은 잠정치입니다. 확정치는 장 마감 후에 나옵니다.
- 지수 수급 단위는 **억원**, 종목 수급 단위는 **주**입니다.

## 면책

이 프로젝트는 공개된 시장 데이터를 정리해 보여주는 **정보 도구**입니다.
투자 자문이나 매매 권유가 아니며, 수치에 오류나 지연이 있을 수 있습니다.
투자 판단과 그 결과에 대한 책임은 투자자 본인에게 있습니다.
